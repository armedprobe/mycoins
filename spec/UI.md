# UI

Требования к интерфейсу: LCL, нативные виджетсеты Win64 и macOS, минимализм.

## Принцип

Внешний вид задаётся геометрией, типографикой и плотностью, а не темой. Любое
требование проверяется грепом по `.lfm` или таблицей свойств. Дизайнерских
изысков нет: предсказуемость важнее выразительности.

## Размеры

| Величина | Значение |
|---|---|
| Шрифт формы | 10pt, семейство системное |
| Единица отступа | 8px; допустимо 0 / 8 / 16 / 24 |
| Padding контейнера | 16 |
| Зазор в ряду | 8 |
| Зазор между секциями | 16 |
| Высота поля и кнопки | 32, через `Constraints.MinHeight` |
| Высота строки списка | 28 |
| Минимальная ширина колонки | 80 |
| Минимальный размер диалога | 360×240 |
| Высота тулбара | 40, `Flat` |

## Компоновка

- Только `Align` и `BorderSpacing`. `Left`/`Top` руками не задаются.
- Ресайз — `Align := alClient` + `Anchors`. Фиксированные `Width`/`Height`
  недопустимы у контролов, чей размер зависит от текста.
- Глубина вложенности контейнеров ≤ 3.
- Форма макетируется на 96 DPI, `Scaled := True`.

## Типографика

- Одно семейство, два размера: 10pt база, 12pt заголовок секции.
- `Bold` , курсив и UPPERCASE не применяются.
- Группировка — отступами и заголовком-`TLabel`. `TGroupBox`, `TPageControl`,
  `TTabControl` не применяются.

## Цвет

- `Color` формы, панелей, тулбаров, кнопок, меню, статусбара **не задаётся** —
  только системный. `TEdit`, `TMemo`, списки остаются на `clWindow`.
- `Font.Color` допустим только как носитель данных: P&L, ошибки валидации,
  статус сделки, предупреждения.
- Исключение: зебра гридов и подсветка строк, их делаем легким изменением цвета.
- Семантические цвета — четыре константы в `src/ui/uipalette.pas`:
  `clDataPositive`, `clDataNegative`, `clDataWarning`, `clDataMuted`.
  Пара подбирается по яркости `clWindow` при старте: тёмная системная тема
  не должна давать нечитаемый текст.

## Диалоги

- Одна главная форма. Диалог правки — модальный.
- `Enter` — основное действие, `Esc` — отмена. Кнопки дублируют клавиши,
  основная справа снизу, отмена слева от неё.
- Валидация — по `Enter`/`Ok`, не на каждое нажатие. Показываются все ошибки
  сразу, фокус на первое невалидное поле.
- Сообщение об ошибке — фиксированная строка внизу диалога, высота 32,
  `clDataNegative`. `TLabel` под полем не применяется: он двигает компоновку.
- `ShowMessage` и модальные окна — только для подтверждения удаления.

## Списки

- Данные виртуальные: `TVirtualStringTree`, не `TDBGrid`.
- Выделение — целая строка, без focus-rect. Inline-редактирование отсутствует,
  правка — через диалог.
- Выравнивание: числа вправо, даты и текст влево.
- Двойной клик — открыть, `Ins` — новый, `Del` — удалить, `F5` — обновить.
- Сортировка кликом по заголовку, направление — символом в тексте заголовка.

## Клавиатура

- `TabOrder` совпадает с визуальным порядком.
- Акселератор у каждой кнопки и пункта меню, уникальный в пределах формы.
- При открытии фокус — на первом осмысленном поле или в списке.

## Запрещено

- `BevelOuter`/`BevelInner` кроме `bvNone`.
- Иконки, картинки, логотипы, сплэши.
- Своя отрисовка: `OnPaint`, `BGRABitmap`, `TCustomControl`.
- Сторонние визуальные пакеты (темы, флэт-контролы).

## Проверка

```
grep -nE "\bColor\s*=" *.lfm        → пусто
grep -n "BevelOuter" *.lfm          → только bvNone
grep -n "Font.Color" *.lfm          → только семантические поля
```
