# Модель mycoins

Учёт купленной криптовалюты: покупки, продажи, партионное списание, позиции, P&L.

## Валюты и курсы

Две независимые величины:

- `cur_id` — в какой валюте заключена сделка.
- `base_cur_id` — основная валюта, в которой считается P&L. По умолчанию из `setting.vs_currency`.

Обе хранятся в каждой сделке. `rate` — курс валюты сделки к основной, **замораживается при вводе**
(`Int64`, `1e8`: `1 cur_id = rate base_cur_id`). При `cur_id = base_cur_id` — ровно `100000000`.

`fxrate` — кэш **текущего** курса, только для предзаполнения поля `rate` в UI. Расчёт от него
не зависит, истории курсов нет. Курса в кэше нет — поле пустое, пользователь вводит руками;
подстановок вида `1.0` и «ближайшей даты» нет.

### Источник курсов

`GET https://api.nbrb.by/exrates/rates?periodicity=0` — официальный курс НБРБ, без ключа.

- Обновление: раз в сутки; повторный запрос не раньше следующего дня по `fetched_at`.
- НБРБ отдаёт только `X → BYN`, поэтому BYN — пивот: при `base = byn` курс берётся напрямую,
  при `cur = byn` — обратная величина, иначе `X→BYN / base→BYN`. Пересчёт в `Double`.
- `Cur_Scale` нормализуется: `rate = Cur_OfficialRate / Cur_Scale` (RUB — за 100, IRR — за 100000).
- Источник в настройку не выносим: смена источника — правка кода, схема не меняется.

Списание возможно только между сделками с одним `base_cur_id`: себестоимость партии пересчитать
в другую базовую валюту нечем. Позиции и P&L агрегируются в разрезе `(coin_id, base_cur_id)`.

## Формат хранения

Масштаб фиксированный, всё целое, кроме производной стоимости.

| Величина | Тип | Масштаб | Пример |
|---|---|---|---|
| количество `Qty` | `Int64` | `1e8` | `0.12345678` → `12345678` |
| цена `Price` | `Int64` | `1e8` в `cur_id` | `0.0000382` → `3820` |
| сумма `Fee`, итог сделки | `Int64` | `1e4` в `cur_id` | `12.3456` → `123456` |
| курс `Rate` | `Int64` | `1e8` | `2.84000000` → `284000000` |
| стоимость, себестоимость, P&L | `Double` | — | производная |

- `Double` — только для стоимости: в БД не хранится, не вводится, не сравнивается на равенство.
- Лишние знаки — ошибка, а не округление: `'1.23456'` для суммы отклоняется, решение об
  округлении принимает вызывающий код.
- `MulDivRound` — только для Int64-масштабирования, не для `Qty * Price`.
- `rate` в сделке — входная величина, а не производная: P&L закрытых сделок не меняется при
  изменении курсов.

## Партионный учёт

Покупка — партия. Продажа списывает количество с произвольного набора партий,
связь — таблица `lotusage` (`sale_id`, `purchase_id`, `qty`).

- Порядок списания выбирает пользователь. FIFO — только сортировка списка партий в UI
  (`occurred_on, purchase_id`), не правило учёта.
- `Σ lotusage.qty` по продаже = `sale.qty`; по партии ≤ `purchase.qty`.
- Все партии продажи: тот же `coin_id`, тот же `base_cur_id`, `occurred_on ≤ sale.occurred_on`.
- Правка или удаление партии с непустым `lotusage` — исключение; удаление продажи без
  `lotusage` — исключение. Правка `qty`/`occurred_on`/`coin_id`/`base_cur_id` — вместе с
  перевалидацией списаний.
- Вставка покупки задним числом разрешена: связи задаются явно, цепочек нет.

## Расчёт P&L

Всё в `Double`, в `base_cur_id` соответствующей сделки.

- Себестоимость партии: `qty*price*rate/1e8 + fee*rate/1e4`.
- Списание: `cost * used/qty`; при полном списании партии — `cost` целиком.
- Выручка продажи: `qty*price*rate/1e8 − fee*rate/1e4`.
- P&L продажи: выручка − `Σ` списаний.
- Остаток позиции: `Σ` остатков qty и `Σ` остатков себестоимости по партиям.

`Qty*Price` в `Int64` переполняется уже на 1 BTC, поэтому произведение — в `Double`.
Продажа больше остатка — исключение, а не зажим в ноль.

## Котировки

Публичный CoinGecko `/api/v3/simple/price` (без ключа), кэш в `quote` в разрезе
`(coin_id, cur_id)`. Котировки влияют только на оценку текущей стоимости, в P&L не входят.

## Именование

- Схема БД — `spec/schema.dbml`, источник правды для DDL.
- Сущности — только в единственном числе: `purchase`, `sale`, `quote`, `setting`.
- Связующие таблицы — по смыслу связи: `lotusage`.
- Справочники — таблицы `<сущность>ref`: `coinref`, `curref`.
- Первичный ключ справочника — бизнес-код (`coinref.coin_id`, `curref.cur_id`), не суррогатный id.
- Коды валют и монет — нижний регистр; `cur_id` — ISO-4217, `coin_id` — CoinGecko.

## Справочники

### COINREF

Справочник монет — таблица `coinref`.

- Источник списка: `GET /api/v3/coins/list` (~21 500 записей, 1.44 МБ).
- Поля: `coin_id` — TEXT, первичный ключ (`ripple`, `shiba-inu`, не `xrp`);
  `symbol` — TEXT, для отображения, не уникален; `name` — TEXT, UTF-8, возможен юникод;
  `icon_url` — TEXT, URL иконки, `NULL` допустим.
- Обновление списка: импорт при первом запуске, далее раз в сутки. На каждый запрос цен — нет.

#### Иконка

`coins/list` иконку не отдаёт, поэтому она грузится отдельно и лениво — `GET /api/v3/coins/{id}`,
поле `image.small`, пишется в `icon_url`.

- Хранится URL, загрузка при первом появлении монеты в сделке или при первом выборе в списке.
- `icon_url IS NULL` — нормальное состояние «ещё не загружена», а не ошибка.


### CURREF

Справочник валют учёта — таблица `curref`.

- Поля: `cur_id` — TEXT, первичный ключ (ISO-4217, нижний регистр); `cur_label` — подпись для UI.
- Обновление: заполняется при создании схемы, извне не обновляется. Новая валюта — только
  вручную, вместе с новым справочным рядом.
