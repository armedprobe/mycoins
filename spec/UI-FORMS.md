# Формы

Как собирается любая форма приложения. Эталон — `src/ui/uimain.lfm` + `src/ui/uimain.pas`.

Требования (цвет, шрифт, запреты) — в `spec/UI.md`. Здесь — анатомия и соглашения,
по которым новые формы делаются копированием эталона, а не изобретением заново.

## Инвариант

`.lfm` — единственный источник правды по компоновке. Всё, что можно проверить грепом
по `.lfm`, проверяется там. Код формы не расставляет контролы: он только заполняет данными.
Исключение одно — грид-карточка главного экрана: она создаётся кодом (см. ниже),
потому что настраивается программно целиком и в дизайнере её настраивать нечего.

## Архетип «экран»

Главная форма. Одна на приложение.

```
┌ mnuMain   alTop     меню
├ pnlTop    alTop  40 тулбар
├ <тело>    alClient
└ sbMain    alBottom 24 статусбар
```

- Тело — ровно один контрол `alClient` с `BorderSpacing` 16 со всех сторон.
- Тулбар: кнопки `alLeft` (96×32), частые действия. Редкие — в меню.
  Разделитель групп — `BorderSpacing.Left = 24`, не `TBevel`.
- Правая часть тулбара — фильтры (`alRight`, объявляются раньше «левых»).
- Заголовок секции (`TLabel`, 12pt) нужен только если у экрана больше одной
  таблицы. Одна таблица — заголовки колонок сами всё говорят.

## Архетип «диалог»

Правка одной записи. Модальный.

```
┌ pnlBody    alClient   BorderSpacing 16
│   строка   alTop 40    lbl (Width 120, alLeft) + контрол (alClient)
│   ...
├ pnlError   alBottom 32  Visible = False, Font.Color = clDataNegative
└ pnlButtons alBottom 40  [Отмена alRight][OK alRight]
```

- Поле = контрол с `Constraints.MinHeight = 32`; подпись — `alLeft` фиксированной
  ширины 120, а не `TLabel` над полем.
- Шаг строки 40 = 32 поля + 8 зазора. Две колонки в строке — подпанели
  `alLeft`/`alClient` внутри строки (глубина 3 — предел).
- `Enter` — `btnOk.Default`, `Esc` — `btnCancel.Cancel`.
- Ошибки — только в `pnlError`, все сразу, фокус на первое невалидное поле.

## Порядок объявления

Стыковка идёт в порядке записи в `.lfm`: объявленный раньше `alTop` — выше.
Для `alBottom` наоборот — объявленный раньше уходит к нижнему краю, поэтому
`pnlButtons` объявляется до `pnlError`. `alClient` — последним в своём родителе.

## Грид-карточка

Класс — `TGridCard` (`src/ui/uigrid.pas`), обёртка над `TLazVirtualStringTree`
(пакет `laz.virtualtreeview_package` из поставки Lazarus). Дерево, раскрытие,
сортировку, выделение и клавиатуру даёт VST; свои — только обработчики
отрисовки (шапка, плашки P&L, фоны строк, текст ячеек) и страницы. Не `TDBGrid`.
Требования к виду — `spec/intent-gui-design-1.md`.

```
TGridCard (TCustomPanel, Color clGridLine, BorderWidth 1 — рамка карточки)
├ TLazVirtualStringTree  alClient   шапка 40, строки 28
└ панель                 alBottom 40  «Стр. 2 из 7 · 19–36 из 120»      Назад  Вперёд
```

- «Назад»/«Вперёд» — подписи-ссылки (`TLabel`), не кнопки: в покое цвет подписи
  страниц (`clGridMuted`), при наведении — `clGridText` с подчёркиванием и
  курсор-рука, недоступная — `clGridLine` без реакции. `Enabled` у `TLabel` не
  используется: на Windows недоступная подпись рисуется системным «вдавленным»
  серым.

- Рамка и линия над панелью — фон обёртки, просвечивающий через `BorderWidth`
  и `BorderSpacing.Top = 1` панели; своей отрисовки у обёртки нет.
- Метрики заданы в логических единицах 96 DPI и умножаются на DPI экрана
  (`Px`); шрифт — системный 10pt, наследуется от формы.

### Страницы

Скролла нет (`ScrollBars = ssNone`), только постраничный вывод.

- Число строк на странице — `ClientHeight div DefaultNodeHeight` дерева: зависит
  от высоты окна, высота строки не меняется.
- Страница — срез плоского списка видимых строк (позиции и операции раскрытых
  позиций). Всё вне среза скрыто `IsFiltered`.
- Если срез начинается с операции, её позиция повторяется первой строкой
  страницы (занимает одно место): `vsFiltered` не скрывает детей, поэтому
  позиция просто остаётся неотфильтрованной.
- Пересчёт — при раскрытии, сворачивании и ресайзе. Открывается страница со
  строкой в фокусе; при сворачивании — со свёрнутой позицией. Сортировка —
  первая страница.
- Листание: ссылки панели, колесо (щелчок — страница), `PgUp`/`PgDn`;
  `Up`/`Down` на краю страницы переходят на соседнюю, `Ctrl+Home`/`Ctrl+End` —
  к началу и концу списка.
- Выделение — только на текущей странице: `Ctrl+A` выделяет страницу, при
  листании выделение снимается, скрытые строки из Shift-диапазона снимаются.
### Колонки и строки

- Колонки описываются в коде формы (`FGrid.AddColumn`) в `FormCreate`:
  `ColId` (номер в модели, он же приходит в события; хранится в `Tag` колонки),
  подпись, ширина, выравнивание, вид ячейки (`gkText` / `gkBadge`). Первая
  колонка — дерево и растягиваемая (`MainColumn`, `AutoSizeIndex`).
- Ширины по умолчанию — `190/110/95/95/95/80/100/110`, минимум 80. Изменение
  ширины окна распределяется по колонкам (`hoAutoSpring`); горизонтального
  скролла нет.
- Колонки не перетаскиваются (`hoDrag` выключен). Ресайз, меню колонки
  (сортировка, сброс сортировки, скрыть, сбросить набор, подогнать ширину по строкам страницы) —
  в гриде.
- Отступ содержимого 16 слева (`Margin`) и справа у колонок с правым
  выравниванием; отдельной колонки выбора нет.
- Фон позиции (первый уровень) — `clGridHover`. Треугольник раскрытия —
  штатный VST, отступ уровня 16 (`Indent`). По умолчанию всё свёрнуто.
- Текст ячеек рисуется в `OnDrawText` с обрезанием `…` по фактическому шрифту
  (см. «Грабли»).
- Чекбоксов выбора нет: выделение — фоном строки (клик, Shift/Ctrl, `Ctrl+A`).
- Грид создаётся кодом (`CreateGrid` в `FormCreate`): в `.lfm` его нет, поэтому
  форма открывается в IDE без регистрации компонента. Это единственное
  исключение из правила «компоновка — в `.lfm`».
- Вид на момент первого спайка — `spec/ui-grid-spike.png`.

## Цвет данных

Грид-карточка на своих фиксированных токенах `clGrid*` из `src/ui/uipalette.pas`
(обычный текст, приглушённый, фон под курсором, выделение, плашки P&L). Стиль
ячейки приходит из формы:

```
P&L > 0 → gsPositive (плашка), < 0 → gsNegative, нет значения → gsMuted (—)
```

Выделение и неактивное окно цвета не меняют: фон `clGridSelected`, текст обычный,
плашка P&L сохраняет свои цвета. Семантические `clData*` — для остальных экранов.

## Числа и даты

Форматирование — `src/ui/uinumfmt.pas`, не `FloatToStr` на месте.

| Что | Формат | Пример |
|---|---|---|
| Кол-во (1e8) | `#,##0.########` | `0.12345678` |
| Цена (1e8) | `#,##0.00########` | `96 100.00`, `0.0000382` |
| Курс (1e8) | `#,##0.00####` | `2.8400` |
| Сумма (Double) | `#,##0.00` | `11 866.02` |
| P&L | `#,##0.00` + `+` | `+3 979.21`, `-900.00` |

Разделитель тысяч — пробел, десятичный — точка, дата — `YYYY-MM-DD`
(ставится в `mycoins.lpr` до создания форм).

## Именование

Префикс — тип контрола, далее смысл, CamelCase:

| Префикс | Класс |
|---|---|
| `mnu` | `TMenuItem` |
| `pnl` | `TPanel` |
| `lbl` | `TLabel` |
| `btn` | `TButton` |
| `cbo` | `TComboBox` |
| `grid` | `TGridCard` (VST внутри; создаётся кодом, в `.lfm` не пишется) |
| `sb` | `TStatusBar` |

- Обработчик — `<контрол><Событие>`: `btnRefreshClick`, `GridGetCell`.
- Поля класса — `F` + имя: `FPortfolio`.
- Общая заглушка «ещё не сделано» — один `NotImplemented(Sender)`, пишет в статусбар.
  Своя заглушка на каждую кнопку — лишний код.

## Клавиатура

`Ins` — новый, `Del` — удалить, `F5` — обновить, двойной клик — открыть.
Акселераторы (`&`) уникальны в пределах формы; `TabOrder` = визуальный порядок;
при открытии фокус — на списке (`ActiveControl`).

## Данные

Форма не знает про SQL. Она читает структуры из слоя данных; плоского списка
строк нет — грид адресует строку парой `TGridRow = (Item, Sub)`: позиция и
операция внутри неё (`Sub = -1` — сама позиция). Индексы — в модели формы,
сортировка их не меняет.

```pascal
FGrid.LoadItems(Length(FPortfolio));   // число позиций
```

- `LoadItems` — перечитать данные; раскрытые позиции, строка в фокусе и
  сортировка сохраняются по индексам модели.
- `OnGetSubCount` — число операций позиции.
- `OnGetCell` — текст и стиль ячейки: `gsMuted` для `—`, `gsPositive`/`gsNegative`
  для P&L (плашка рисуется только для этих двух).
- `OnCompare` — сравнение двух строк одного уровня по колонке, по возрастанию;
  направление и порядок при равенстве (по индексам модели) — забота грида.
- `FocusedRow` — строка в фокусе (`Item = -1`, если её нет).

## Грабли LCL

- Событие, которое пишется в `.lfm`, должно быть `published`: иначе при загрузке
  формы «Unknown property» и приложение не открывается.
- Класс из `.lfm` должен быть зарегистрирован (`RegisterClass` или установленный
  пакет). Грид-карточка этого избегает: она создаётся кодом.
- Ширины/высоты внутри контрола не масштабирует LCL: умножать на DPI самому.
- Файл ресурсов с манифестом (`mycoins.res`) собирает `lazbuild` по флагу
  `UseXPManifest` в `.lpi`, но линкуется он только при `{$R *.res}` в `.lpr`.
  Без этого виджеты рисуются в классическом стиле.
- Русские литералы — `{$codepage utf8}` в юните. Правка `.pas`/`.lfm` через
  PowerShell `Get-Content/Set-Content` перекодирует текст и портит его.
- Литерал с не-ASCII в `+` даёт `UnicodeString` и предупреждение 4104/4105:
  подписи держать в типизированной константе (`OpKindName`), а не клеить на месте.

### VST

- `Font.Color` у дерева в конструкторе сбрасывает `ParentFont` до появления
  родителя: дерево остаётся на шрифте по умолчанию, а не 10pt формы. Цвет
  текста задаётся в `OnPaintText`, не свойством.
- VST решает об обрезании текста по ширине, измеренной до того, как на холст
  буфера выставлен шрифт дерева, и режет строки, которые влезают. Текст ячеек
  рисуется в `OnDrawText` своим `FitText`.
- Перед проходом текста owner-draw шапки VST сужает `PaintRectangle` на 2
  с каждой стороны — вернуть `InflateRect(R, 2, 2)`.
- Строку под курсором (`HotNode`) VST перерисовывает только с `toHotTrack`,
  а тот подчёркивает текст: перерисовка — в `OnHotChange`.
- Вложенные строки инициализируются при первом раскрытии, уже после
  `SortTree`: сортировать их в `OnExpanded`.
- Колесо: `OnMouseWheel` с `Handled := True` — иначе VST сдвигает `OffsetY`/
  `OffsetX` даже без скроллбаров.

## Чек-лист новой формы

1. Скелет скопирован, `Align`/`BorderSpacing`, ни одного `Left`/`Top` в коде.
2. `Constraints.MinWidth/MinHeight`, `Scaled`, шрифт 10pt.
3. Акселераторы уникальны, `TabOrder` по визуальному порядку, `Enter`/`Esc` работают.
4. Строка ошибки одна, `clDataNegative`, `ShowMessage` не используется.
5. Числа — через `uinumfmt.pas`, выравнивание вправо.
6. `grep -nE "\bColor\s*=" *.lfm` — пусто, кроме разрешённого.
